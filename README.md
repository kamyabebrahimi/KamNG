# KamNG

KamNG is a personal Android fork of [PattNG](https://github.com/patterniha/PattNG), based on PattNG 2.3.10-P60 and upstream [v2rayNG](https://github.com/2dust/v2rayNG).

## Current changes

- Independent application ID: `com.kamyab.kamng` (`.fdroid` for the F-Droid flavor).
- KamNG name, APK filenames, launcher shortcuts and update repository.
- Routing presets carried over from the customized PassWall setup: AI Services, ChatGPT, YouTube, Telegram, X, Google and Gaming, with existing Iran and local-network bypasses.
- AI shared login/challenge routing is disabled by default.
- Domain and IP rules are separate so they retain OR behavior.
- GitHub Actions builds installable debug APKs, runs both flavor unit-test suites and checks the native libraries in produced APKs.

Fresh installations receive the KamNG rules as the default Iran preset. Existing rules are retained. To load the preset manually, use **Routing settings > Import predefined rulesets > Iran whitelist**. You can edit each rule's outbound, enable it or change its priority in the existing routing editor.

Custom raw JSON profiles retain their own configuration and routing. Loading these presets does not rewrite a custom JSON profile.

## Download test builds

Open this repository's **Actions** tab. Enable Actions if GitHub has disabled workflows on the new fork, then select **KamNG APK > Run workflow** on `my-releases`. After a successful run, download **KamNG-debug-APKs** from **Artifacts** and extract the APK matching your device.

These are debug-signed testing builds. A stable release signing key must be configured before distributing release updates. Debug signing keys generated by separate clean runners may differ, so subsequent test builds may require uninstalling the previous test installation; export your configuration first.

## Current limits

AmneziaWG and CottenDNS are integrated in the 0.2.0 native-engine build described below. Automatic engine fallback, encrypted backups and additional diagnostic screens are not implemented. Native engines can be standalone routing targets, policy-group members, or the final transport in a proxy chain. Earlier chain positions are rejected because these engines cannot dial a remote server through an Xray upstream hop; ordinary Xray chains retain their existing behavior.

Not run: Android device checks for VPN/proxy-only/root start, stop, reload, revocation and network handover; editor recreation, persistence, IME traversal, TalkBack, keyboard/D-pad activation and light/dark themes. No Android device or emulator is attached here. CI assembly and unit tests do not verify those device scenarios.

## Native engine integration (0.2.0)

AmneziaWG and CottenDNS are selectable in the SOCKS editor. See native/README.md for setup, pinned sources and architecture. The build runs native/JVM tests and packages both engines for all four ABIs.

Not run: physical-device VPN, proxy-only and root connections; screen recreation, TalkBack, keyboard/D-pad and IME traversal; live server handover and stop/restart races. No Android device or emulator is attached.
